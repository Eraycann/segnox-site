02Ne yapabilir, ne yapamaz

Yalan yok. Her satır gerçek koddan, test sonuçlarından veya eksikliklerden.→ tam özellik listesi

✓ ÇALIŞIYOR (MVP 1-4b)

  • Ekran yakalama (DXGI + GDI, çoklu monitör, JPEG karo)
  • Tam fare ve klavye kontrolü — Türkçe Q/F doğru çalışır
  • 9 haneli kodla bağlantı, P2P doğrudan bağlantı
  • Hesap, iki katmanlı doğrulama (TOTP + 10 kurtarma kodu)
  • E-posta doğrulama, parola sıfırlama, davetle kullanıcı ekleme
  • Cihaz kaydı, onay penceresi (WebView2), kapatılamayan çubuk
  • Destek isteği, sohbet, ortak pano, dosya aktarımı
  • Çoklu firma izolasyonu (veritabanı RLS), roller (sahip/yönetici/teknisyen/izleyici)
  • ICE restart (bağlantı kopmasında otomatik yeniden bağlanma)
  • Değiştirilemez denetim kaydı (hash zinciri)
  • Açık REST API + hız sınırı + kota
  • Yönetim paneli (HTML, HTMX tabanlı)
  • Docker ile tek komutla ayağa kalkan sunucu (segnox-server + PostgreSQL + coturn + Caddy)
  • Yedekleme (pgBackRest) + geri yükleme betikleri

✓ KODDA, ✗ DENEMEDİ (5-6. adımlar)

  • H.264 video — Media Foundation MFT kodlayıcı (koddeymiş ama gerçek masaüstünde okunaklılık testi yapılmadı) 3225 → 1518 kbit/s ⚠️ kullanıcı gözlemi gerekiyor
  • Gözetimsiz erişim — SYSTEM servis kipi + cihaz parolası (koddeymiş, gerçek UAC/kilit ekranı senaryolarında denemedi)
  • Servis kipinde dosya transferi — kod var ama gerçek kilitli ekranda test edilmedi
  • Otomatik güncelleme — imzalı manifest (koddeymiş, gerçek 1.0.0 → 1.0.1 güncelleme VM'de denemedi)
  • Çoklu izleyici — "N kişi bağlı (M izliyor)" (e2e test geçti, gerçek birden çok izleyici senaryosunda kontrol edilmedi)

Not: Bu özellikler kod içinde yaklaşık 95% tamamlanmıştır. Ancak "MVP" başlığı altında yer alanlara benzer bir "tamam" ifadesi koyarak, kullanıcıların gerçekten çalıştıklarını düşünmelerini önlemek gerekir.

05CI / CD — 4 test (her push) — sade açıklama

1 — windows

Derleme + kalite. Windows'da Go derler, vet hatalar, lint güvenlik, test çalıştırır. Kod değişince önce bu geçer.

2 — linux

Race kontrolü. Ubuntu'da go test -race eşzamanlı hataları yakalar. Windows'da yok.

3 — e2e (Edge)

Müşteri deneyimi. Tarayici 9 haneli kod girer baglan go gor fare/klavye gercek kullanici gibi.

4 — coturn-probe

Güvenlik. TURN sunucusu 10 tehlikeye relay vermez reddeder. Açık relay güvenlik hatasi.

06PostgreSQL — sadelik

1 — İletişim yok: PostgreSQL yalnız iç ağda (db ağı), sunucu sadece bu ağdan erişir; port dışarı açılmaz.
2 — Firma izolasyonu: Her tablo tenant_id taşır + FORCE kural. Sorgular önceden filtrelenir; başka firmanin verisi görünmez.
3 — Parola: SEGNOX_APP_DB_PASSWORD sadece postgres servisi ve migrate görür; sunucuda log/dışarı sızmaz.
4 — Yedek: Her degisiklik pgBackRest ile Hetzner Object Storage'a (şifreli) yazilir; her ay geri yükleme testi yapılır.

07VPS / Test — neden bu şekilde

Tek cümle: Ajan (segnox-agent.exe) yalnız Windows'ta çalışır, bu yüzden müşteri tarafıyla ayni ortamda test etmek zorunludur; sunucunun Linux olması ayrı bir konu, müşteri deneyimi Windows'ta test edilir. Docker'la Linux sunucusu da kurulabilir ama müşteri tarafı eksik kalmaması için Windows makine tercih edilir.
