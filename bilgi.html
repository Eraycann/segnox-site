6 · Nasıl çalışır

6.1 · Sistemde ne var

  MÜŞTERİNİN BİLGİSAYARI              SUNUCU (VPS)            TEKNİSYENİN CİHAZI
  ┌──────────────────────┐            ┌──────────────┐        ┌──────────────┐
  │ segnox-agent (.exe)  │            │ segnox-server│        │  Tarayıcı    │
  │  ├ ekran yakala      │  ① sinyal  │  ├ sinyal WS │        │  (WebRTC)    │
  │  ├ H.264 kodla       │ ─────────► │  ├ REST API  │ ◄───── │  kurulum yok │
  │  ├ fare/klavye       │            │  └ konsol    │        └──────┬───────┘
  │  └ onay penceresi    │            │  PostgreSQL  │               │
  └──────────┬───────────┘            │  coturn, Caddy│               │
             │                        └──────────────┘               │
             └──── ③ WebRTC (veri) doğrudan; olmazsa ② TURN relay ────┘
İki kanal: ① Sinyal (WebSocket, sunucu üzerinden): "şu cihaza bağlan", onay, parola kanıtı. ③ Veri (WebRTC, DTLS ile şifreli): ekran, fare, klavye. Sunucu görüntüyü göremez.

6.2 · Giriş akışı

  1. Müşteri ajanı çalıştırır → cihaz sunucuya kaydolur, 9 haneli kod alır
  2. Teknisyen tarayıcıda kodu girer → sunucu talebi müşterinin ekranına düşürür
  3. Müşteri onay penceresi: Reddet → biter · Kabul → oturum açılır
  4. Cihaz parolası varsa teknisyen girer (kanıt gider, parola gitmez)
  5. ICE: doğrudan yol denenir, olmazsa TURN
  6. Görüntü akar; izleme (view) rolünde girdi gitmez
Onay penceresi açıkken uzaktan girdi engellenir; yoksa dolandırıcı müşterinin onayına kendisi tıklardı.

6.3 · Gözetimsiz erişim (servis kipi, K-26)

  SYSTEM servisi (açılışta otomatik)
     └─► oturumda SYSTEM yardımcı  ← ekranı yakalar, tuş gönderir
            └─ named pipe (ACL kilitli) ─► kullanıcı token'lı ui-host (onay penceresi)

Amaç: kullanıcı girmese de, ekran kilitliyken ve UAC'de de müdahale. Hata olursa kapalı kalır (fail-closed). Kurulum ve ui-host VM'de doğrulandı; UAC/kilit gözle denenmedi.

6.4 · Veri izolasyonu (RLS)

  platform → bayi → müşteri firma      (her tabloda tenant_id + RLS, FORCE)
  Uygulama segnox_app rolüyle bağlanır, BYPASSRLS yok; tek kapı: store.InTenantTx

Denetim ekibine cevap: "firma verisi başka firmaya sızar mı?" — veritabanının kendisi engeller.

6.5 · Ağ (STUN / TURN / ICE)

Müşteri ve teknisyen farklı ağlarda; adresleri dışarıdan görünmez. ICE sırayla dener, kullanıcı ayar yapmaz:

  host   aynı ağ              en hızlı, ücretsiz
  srflx  STUN ile bulunan IP   hızlı, ücretsiz
  relay  TURN üzerinden        her yerde çalışır, yavaş, trafik = para
  • STUN yalnız genel IP'yi öğretir; TURN veriyi kendisi taşır.
  • İkisi de kendi coturn sunucumuzda; TURN kimliği HMAC ile sunucudan alınır, anahtarsız relay kullanılamaz.
  • Üçüncü taraf STUN (Google/Cloudflare) kullanılmaz: IP sızar, KVKK (K-25).
  • Ayar: SEGNOX_STUN, SEGNOX_TURN_URLS. Ajan logunda candidate_type host/srflx/relay görünür.

6.7 · Sözlük

Ajan
Müşterinin bilgisayarındaki program; ekranı yakalar, tuş gönderir.
Teknisyen
Yardım eden kişi; tarayıcıdan bağlanır.
P2P / relay
Doğrudan bağlantı (ucuz, hızlı) / TURN üzerinden (maliyetli). Raporlar sayfası oranı gösterir.
NAT
Ev ağındaki cihazların dış IP'yi paylaşması; doğrudan bağlantıyı zorlaştırır.
ICE restart
Kopan bağlantının kendiliğinden yeniden denenmesi.
Kiracı
Bir firma; platform → bayi → müşteri sırasıyla daralır.
SYSTEM
Windows'un en yetkili hesabı; gözetimsiz erişimin anahtarı.
fail-closed
Emin olunamayan durumda izin verme, kapat.
